# 后端代码规范

- Java 生产代码、测试和工具脚本均使用显式局部变量类型，不使用 `var`，包括循环变量和 try-with-resources。
- 新增或修改业务类型时使用明确的单类型导入，避免通配符导入隐藏同名冲突。核对自动导入的包，不引入与业务无关的 JDK 或第三方类型。
- 返回 DTO 使用明确的业务名称并注明用途，例如 `PublicationCardView` 是文章列表的只读返回模型，不能作为数据库实体或领域聚合使用。
- 简单数据库操作沿用 MyBatis-Plus；复杂联表投影使用 Mapper XML。跨模块能力通过端口与 composition 适配。
- HTTP JSON 返回统一使用 `Result`。类型或命名调整保持接口字段和业务行为兼容，并运行受影响的编译及测试。
- 业务规则、并发边界和重要数据约束写清楚中文注释。可复用值使用已有常量或明确命名的常量。
