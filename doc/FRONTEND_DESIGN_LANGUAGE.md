# AriesHub 视觉与交互规范

状态：2026-09-29，根据确认的 Cosmos 方向落地公开首页、登录、注册和社区成员区。旧黑白杂志、暖色书房、科技渐变及原主站内容布局不再作为设计依据。

更新：2026-10-07。全站继续采用 Cosmos 方向：黑白极简界面、画廊内容、大留白和克制动效。账号与内容后台遵循同一套视觉语言；禁止暖色名片、绿色主按钮、米黄色表单卡和旧杂志风粗黑标题。

### 布局与画廊

- 一个区块表达一个主题。以对齐、间距和文字层级组织内容，避免每个功能套边框卡片。
- 桌面内容宽度 1120–1320px；画廊可更宽，正文阅读宽度 640–720px。页面两侧留 32–64px，手机 16–24px。
- 公开画廊使用不同长宽比与错位关系，保留图片自身视觉特征。不要把所有图片强制裁成同一横幅，不让文字压在复杂图像上。
- 产品页优先稳定网格；账号采用资料预览与编辑区域的非对称双栏，后台采用开放内容列表及双栏编辑器。移动端单列，操作与内容顺序保持一致。
- 页面标题与内容区间距约 48–64px，分区间距约 32–48px；公开展示段落可使用 80–120px。业务表格可以更密，不能照搬首页的巨幅装饰。

### 字体与文案

- 首页主标题 48–78px、功能页标题 36–56px、分区标题 20–26px、正文 14–16px、标签与元信息 11–13px；移动端主标题 30–40px。
- 标题字重 400–550、字距约 -0.02em 至 -0.05em；中文保持可读行高。避免全页粗黑字、衬线标题及过多大写英文标签。
- 标题直接说明任务，如「你的个人资料」「内容后台」。说明短且具体，不使用营销口号掩盖功能；加载、错误与空状态同样清楚。

### 色彩与表面

- 彩色来自真实图片、视频、用户头像和品牌图标；不通过随机绿色、桃色或暖色面板制造层次。
- 主操作黑底白字；次操作白底细灰边或纯文字。必要的错误、警告、成功可以使用语义色，同时提供文字/图标，不能仅靠颜色区分。
- 普通内容不加大阴影；只给菜单等真实浮层使用轻阴影。分区采用单条细线；圆角不统一套满所有容器。
- 用户菜单、Select 等 portal 浮层也必须采用中性主题，不能继承遗留暖色根变量。

### 控件与状态

- 主按钮与输入高度约 48–52px，按钮胶囊，输入约 12–17px 圆角；手机触控目标不小于 44px。
- 菜单支持鼠标、键盘、Escape、点击外部关闭与焦点回收。操作进行中禁止重复提交，失败保留输入，不展示模拟成功。
- 表单标签、字数、校验错误与保存状态明确；图片提供上传预览和移除。资料保存立即同步顶部头像及昵称。
- 不使用未经授权的图片填充后台，也不编造管理员统计。后台状态与时间来自 API。

### 动效与响应式

- 界面反馈约 150–250ms，内容进入约 350–600ms；GSAP 只负责 transform/opacity，路由或组件卸载必须清理。
- 图片展开、轻微位移服务于内容关系；账号与后台不添加持续漂浮装饰。减少动态效果时全部内容直接可见。
- 在 1440px、768px、390px 验证；画廊随宽度减列，表单和编辑器改为单栏，顶部用户入口保留，无横向溢出。

### 后续页面设计顺序

先阅读本规范，再对照相邻页面 → 明确页面任务与真实数据 → 确定灰阶网格和留白 → 使用现有控件 → 添加真实内容影像 → 完成加载、空、错误、权限状态 → 桌面和手机截图复核。所有新的账号、后台与内容页面都按这一顺序实施；本规范优先于通用设计技能的字体、色彩或装饰建议。

## 产品定位与文案

AriesHub 是主理人持续发布深度内容、成员围绕实践交流的 AI 社区。首页负责介绍与邀请，不是付费案例货架，也不暗示提供 AI 生成服务或与工具厂商有合作。标题短、每屏一件事；付费说明放在深度内容与加入入口附近。讨论样例、概念影像和内容预览必须有相应标识；不编造用户数、口碑、合作伙伴或主理人经历。

公开首页顺序：品牌首屏 → 影像 → 实践方向轮播 → 深度内容 → 社区讨论 → 主理人 → 加入入口。未登录访客可查看社区介绍，以及内容的公开标题、成果、摘要、免费预览、交付说明与积分价格；完整正文和资源按权益开放。

成员区以社区和持续学习为中心。登录后先进入 `/home`，首先看到继续阅读和已加入内容，再看到相关推荐、最新发布和围绕内容展开的讨论。一级导航固定为「首页 / 探索 / 讨论 / 我的空间」；「实战案例」「文章」「课程」是内容类型，「案例库」只在需要归档实战案例时使用，不作为整个社区的名称。

## 视觉

- 字体：Arial / Helvetica Neue / PingFang SC / Microsoft YaHei / sans-serif。禁止宋体、衬线标题、Impact 压缩大字。主标题 42–78px，正文 13–17px，标题字重 450–550。
- 底色以中性 #FAFAFA 为新页面采用值，已有公开页 #FAFAF8 保持低差异过渡；文字 #151515，辅助文字灰色；图片、真实产品图标提供颜色。登录左侧白色，右侧浅灰。
- 首屏以留白为主，产品图标约 58–100px，沿外围分布；中心、顶部、底部使用白色渐变羽化，文字始终清楚。真实图标来自本地 SVG，不用生成图替代品牌。
- 内容容器桌面 1120px，大屏 1320px；区块间距约 100px，手机 65px。避免密集功能卡和价格墙。
- 控件采用项目现有 shadcn（Base UI）组件及 Tailwind。主按钮胶囊形，高 52px，黑底白字；输入高 52px，17px 圆角，浅边框。hover、active、focus-visible、disabled 都要有反馈。
- 公开站样式入口 `src/app/cosmos.css`；成员区样式入口 `src/app/community.css`，共同限制在 `.cosmos-site` / `.community-hub` 作用域内，不让旧主题污染新页面。复杂画廊与社区信息布局用专用 CSS，按钮、输入框和文本域使用项目已有的 shadcn（Base UI）组件。

## 动效与顶部入口

GSAP React 生命周期以 gsap.matchMedia + 清理实现；ScrollTrigger 负责滚动联动。图标 5–9 秒往复轻浮动，伴随少量 X/Y/Z 旋转；不同卡片错开相位。首屏随滚动缓慢扩大、向下移动、淡出；影片随滚动放大；内容区从下方展开。只动画 transform/opacity，避免每帧改布局。

顶部「今天，想探索什么？」为可展开导航胶囊，不是尚未实现的搜索框。呼吸光点、展开宽度与内容反馈，提供灵感、文章、讨论、注册入口。支持 Escape、点击外部关闭及键盘访问。

prefers-reduced-motion 下禁用漂浮、滚动位移、呼吸和步骤动画，保持全部内容与操作可用。视频按用户操作播放，默认静音，提供播放/暂停/静音及加载失败提示。

## 登录与注册

桌面 50/50 分栏，左侧 340–360px 窄表单居中，顶部品牌标志、底部字标；右侧错落图片。手机隐藏装饰画廊，保留完整表单及触控空间。

登录：邮箱 + 密码，不要求验证码。注册：邮箱 → 邮箱验证码 → 密码 → 昵称 → 兴趣方向。兴趣可不选，目前不新增后端字段。每步只展示当前任务，返回保留输入。右侧图片先收拢淡出，再换构图展开；约 0.3 秒收拢、0.65 秒展开。

保留既有 `/api/v1/auth` 接口、服务端限流错误、邮件错误 traceId、验证码倒计时。验证码的最终真实性仍由注册接口校验。正式注册成功进入 `/home`；兴趣数据接入后端留待业务重构。账号与安全设置仍在 `/account`。

「仅体验页面流程」显式开启演示：不发送邮件、不创建账号、不写认证 Cookie，演示验证码 123456，完成后进入 /discover?preview=1。仅兴趣保存于 sessionStorage；不持久化邮箱、密码和验证码。演示不可视为真实登录或权益授权。

## 认证错误交互

密码输入只保留页面自定义的显示/隐藏按钮，隐藏 Edge 原生 reveal 控件。注册发码或最终提交返回 EMAIL_ALREADY_REGISTERED 时，跳转登录页并预填邮箱，密码不带入。

登录凭证由 Sa-Token 写入同域 HttpOnly Cookie，不把 JWT 或 token 存入 `localStorage`。全局 `AuthSessionProvider` 只在内存中保存当前用户展示状态，并由服务端是否存在会话 Cookie 决定首帧；未登录首屏不请求 `/me`，登录和退出事件会立即同步状态并刷新服务端路由缓存。已登录时，落地页的加入入口统一变为「进入社区」并指向 `/home`。

服务端限流响应携带 retryAfterSeconds 与 Retry-After，取自 Redis 当前窗口的剩余时间。前端显示分秒倒计时，等待期间禁止重复提交，到期恢复按钮；旧服务未提供时间时保留原错误提示，不编造倒计时。本次未调整原有限额与计数顺序。

旧版设计探索文档、整页概念稿及未使用的灰阶配图已清理；本规范与 ASSET_SOURCES.md 为当前参考，页面仍使用的彩色配图保留。

## 社区成员区

成员页面使用入口守卫：无会话 Cookie 时重定向登录；有 Cookie 时先由 Java `/users/me` 验证，验证完成前不显示成员区，失效会话转向登录，服务异常提供重试。后台额外检查管理员角色。公开探索与公开详情保留访客访问；演示流程不获得成员权限。

- `/home`：成员首页。继续阅读、已加入内容、相关推荐和最新发布构成内容主线；成员在线状态、讨论回复和「正在实践」让社区关系在首屏可见。
- `/discover` 与 `/publications`：内容探索。支持类型、分类和关键词过滤，公开展示摘要、免费预览范围、交付内容与积分价格。
- `/publications/[slug]`：公开内容详情。目录清楚区分免费章节与完整章节；积分权益未接入时明确显示「不会扣除积分」。
- `/learn/[slug]`：阅读器。桌面三栏、手机横向章节导航；记录阅读章节，并提供收藏、点赞和围绕文章讨论的入口。
- `/community`：讨论。成员围绕实战内容提问、分享复现过程和作品反馈；示例讨论必须标为「社区预览」。
- `/my-content`：我的空间。集中显示收藏、点赞和阅读记录。
- `/members`：主理人与成员场景。示例资料必须标明版式或场景示例，不编造真实成员规模。

现阶段收藏、点赞和阅读进度只保存在当前浏览器的 `localStorage` 中，页脚持续提示这一点。评论与回复的服务端树形接口已经建立，前端讨论原型将在下一轮切换到该接口；本地示例不代表真实发布、内容已解锁或账号已获得权益。通知按钮在真实数据接入前保持禁用。

成员区的进入动画使用 `@gsap/react` 的 `useGSAP`，随路由变化自动清理；只改变 `transform` 和 `opacity`。`prefers-reduced-motion` 下不创建进入动画，所有内容直接可见。

## 验收

检查公开首页、登录、五步注册，以及成员首页、探索、内容详情、阅读器、讨论和我的空间，覆盖桌面与 390px 手机。验证顶部入口鼠标/键盘、轮播切换、视频实际播放、返回保留值、错误提示、无横向溢出、所有图标可加载、刷新认证占位不闪登录按钮；成员区还需验证收藏、点赞、阅读进度和本地讨论可跨页面保留。构建、类型检查、lint、格式检查及对应端到端测试必须通过。

## 运营后台与写作工作台

后台沿用 Cosmos 黑白中性与画廊审美，但使用适合管理的信息密度：白色固定侧栏、细边框工作区、浅灰画布、黑色主操作。统计使用真实记录；空状态保留创作入口，不用假数据装饰。移动端收起侧栏，表格只在自身区域横向滚动。

写作是页面主角：正文纸面与发布设置并列，工具栏集中提供格式及素材操作，标题/摘要直接在纸面编辑。公开预览与完整正文清楚区分；分类、类型、封面、定价、精选及交付说明在右侧。提供阅读预览、Markdown 源码、Ctrl/⌘+S、既有草稿自动保存与离开保护。任何保存错误都保留当前输入。功能边界详见 [运营后台](ADMIN_WORKSPACE.md)。
