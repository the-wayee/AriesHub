# 社区动态

首页「社区的此刻」通过 `GET /api/v1/community/activities` 展示真实动态。必须登录，每页最多 24 条；昵称、头像签名和目标链接由后端提供。Tab 按类型筛选，每次只展示三条，持续匀速向上滚动，预取历史后无缝循环。悬浮时立即暂停，移开后从当前位置继续；键盘聚焦、页面隐藏或减少动态偏好时也暂停，不提供轮播操作按钮。本页面发生互动后更新，悬浮阅读或键盘操作时保留当前位置；轮播过程中不定时重置列表，以免历史条目始终播放不到。八种事件各有独立图标和颜色，位于头像旁。

## 数据与领域

`activity` 是独立的动态领域，`community_events` 是跨业务社区事件表。记录来源事件键、操作者、事件类型、目标类型与标识、发生时间，不复制账号邮件、评论正文、付费内容或附件下载链接。事件没有公开创建接口，不能由浏览器任意填写行为。

各模块发布自己的应用事件，`composition/CommunityActivityEventAdapter` 同步监听并调用动态用例。动态写入必须加入来源事务，业务失败时一起回滚；数据库唯一 `event_key` 与 `ON CONFLICT` 保证同一事件重投不会重复插入。没有使用提交后监听或异步线程，因此不会出现业务回滚但动态已经提交的情况。将来接入消息队列时，需要另建可靠 outbox 投递，不能直接改成异步监听。

| 来源事实 | 动态类型 |
|---|---|
| 注册成功 | `MEMBER_JOINED` |
| 文章首次发布 | `PUBLICATION_PUBLISHED` |
| 新增点赞、收藏 | `PUBLICATION_LIKE`、`PUBLICATION_BOOKMARK` |
| 首次确认分享 | `PUBLICATION_SHARE` |
| 新评论、回复、评论点赞 | `DISCUSSION_COMMENTED`、`DISCUSSION_REPLIED`、`DISCUSSION_LIKED` |

重复点赞 PUT、重复分享确认及取消操作不会生成新动态；取消后再次点赞是一个新的真实行为。修改已发布文章和再次发布也不会重复生成「首次发布」动态。

`publication_events` 继续承担文章阅读、分享计数及原有去重，不再作为首页动态的数据源。V19 将既有文章互动迁入社区事件表，排除 VIEW；首页不再调用原文章行为接口 `/home/activity`。阅读次数等高频埋点不默认进入公开列表，后续接入新事件时应明确它的展示范围。

## 当前可见性

事件保留历史，展示时重新判断目标。文章下架、分类删除、评论隐藏或自删、根评论隐藏、线程隐藏之后，相关动态不再出现在首页。头像和昵称批量读取，文章摘要仅按数据库 ID 批量查询；讨论模块提供当前可见评论的目标关联和最多 180 字摘录，不跨领域联表；隐藏或删除后不再展示摘录。评论与回复展示自身发言，文章互动展示文章标题。

每次分页最多扫描 100 条候选，过滤后可能少于请求数量，避免历史积累导致无界查询。新成员动态目前不跳转到个人主页；文章和评论动态分别跳转到文章及其评论区。当前可评论业务目标只有文章，新增其他讨论目标时也需扩展组合层的动态目标解析。

## 后续接入

动态类型使用 `CommunityEventKind`，关联对象使用 `CommunitySubjectType`。领域对象和用例参数传递枚举，数据库边界转换为稳定名称，返回 JSON 编码不变。来源事件在组合层通过穷尽的 switch 映射；添加新来源类型时编译器会要求补齐映射，不再通过前缀拼接字符串猜测事件类型。内容目标的公开挂载编码由 `Publication.TARGET_TYPE` 声明，与动态模块自己的对象类型区分管理。

新增功能在所属模块发布应用事件，在组合层映射到社区事件的类型与目标，再补充对应的可见性解析和前端展示动作即可。来源模块不依赖 `activity`，动态领域不依赖 `catalog`、`identity` 或 `discussion`，构建时由架构测试检查这些边界。

## 筛选与向下加载

`GET /api/v1/community/activities?filter=ALL&size=12&before={事件ID}` 返回 `items` 和 `nextCursor`。Tab 的编码集中在 `CommunityActivityFilter`，筛选先于分页执行；全部、新文章、评论回复、互动及新成员都读取同一动态表。按记录 ID 倒序分页，新增动态不会挤动已经加载的历史页。不可见的历史事件同样推进游标，防止空页重复查询；单次候选扫描有上限。

前端在「社区的此刻」列表底部接近可见时继续读取下一页。切换 Tab 重新建立查询快照，旧请求不能覆盖新结果；加载失败保留已有动态与游标，允许重试。列表支持键盘滚动，Tab 支持左右键、Home 与 End。

## 开发示例

`db/demo/R__demo_community_activity.sql` 只在 dev 配置下造数据，包含八种事件、真实评论与回复目标；演示身份禁用登录，事件键保证重复执行幂等。生产只加载 `db/migration`。

分类切换的列表遮罩使用一秒轨道流动动画；请求和动画并行，二者完成后三颗轨道圆点聚拢、扩散，遮罩退场与新列表交叉渐变，不先清空列表再展示数据。刷新期间保留旧列表、固定三行高度并暂停轨道；失败保留旧数据，旧分页响应由请求代次排除。

社区动态不提供手动刷新按钮，切换 Tab 使用上述动画，不卸载旧列表；快速切换以最新代次为准，取消旧分类响应及完成回调。
